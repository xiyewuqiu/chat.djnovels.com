# 会话内消息搜索（接入方指南）

在单个会话里按关键词找消息。接口在引擎 API 网关（默认 `127.0.0.1:65101`），
业务层不需要再包一层——客户端要搜索时走业务层的转发入口（见第 6 节）。

---

## 1. 请求

```
POST /apigateway/hismsgs/search
Content-Type: application/json
appkey: <租户 app_key>
signature: <见引擎 API 鉴权说明>
```

```json
{
  "user_id": "u1",
  "target_id": "g1",
  "channel_type": 2,
  "sub_channel": "",
  "keyword": "书单",
  "limit": 20
}
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `user_id` | 是 | 发起搜索的用户。会话可见性按这个人算 |
| `target_id` | 是 | 单聊是对方 user_id，群聊是 group_id |
| `channel_type` | 是 | `1` 单聊 / `2` 群聊。其他值直接拒绝 |
| `sub_channel` | 否 | 子频道，不传为空 |
| `keyword` | 是 | **2–32 个字符**（按字符算，不是按字节：一个汉字算 1） |
| `limit` | 否 | 命中条数上限，缺省 20，上限 50 |

---

## 2. 响应

```json
{
  "code": 0,
  "data": {
    "hits": [
      {
        "msg_id": "m_1001",
        "sender_id": "u2",
        "msg_time": 1762900000000,
        "msg_type": "jg:text",
        "snippet": "…这周的书单我看过了，第三本…"
      }
    ],
    "count": 1,
    "scanned": 500,
    "candidate_limit": 500
  }
}
```

- `snippet` 是**片段**，不是全文。前后被截断时会带 `…`。
- `scanned` 是这次实际扫了多少条候选，`candidate_limit` 是上限。两者都等于 500 时，
  说明还有更早的消息没被扫到（见第 3 节）。
- 结果是**按时间倒序**的（最近的在前）。

---

## 3. 能力边界（必须知道）

| 边界 | 说明 |
| --- | --- |
| **只搜最近 500 条** | 不是全量检索。会话消息超过 500 条时，更早的搜不到 |
| **只搜文本消息** | `jg:text`。图片、文件、语音、合并转发不参与匹配 |
| **只搜一个会话** | 没有"全局搜索"。跨会话搜索需要客户端逐个会话调 |
| **受保留期约束** | 超出租户保留期（默认 7 天）的消息搜不到，与历史消息查询口径一致 |
| **受可见性约束** | 群聊里：非成员搜不到；群配置"新成员看不到入群前消息"时，入群前的也搜不到 |
| **限频** | 同一 `(appkey, user_id)` 每分钟 20 次，超出返回 `10012` / HTTP 429 |

> 第 1 条是当前实现的硬边界，不是 bug。要搜全量历史，需要给消息建内容索引
> （生成列 + ngram 全文索引），那是独立工程，且会让存储成本上升。

---

## 4. 错误码

| 码 | HTTP | 含义 | 客户端该做什么 |
| --- | --- | --- | --- |
| `0` | 200 | 成功（包括"没有结果"） | 展示空状态 |
| `12004` | — | 参数非法（缺 user_id / channel_type 越界 / 关键词长度不符） | 修参数，别重试 |
| `10007` | 400 | 请求体不是合法 JSON | 修参数 |
| `10012` | 429 | 触发限流 | **退避后重试**，不要立刻重试 |
| `13006` | — | 不是群成员（群聊时） | 引导用户先入群 |

"没有结果"永远返回 `code: 0` 加空 `hits`，不用错误码表达——空结果是正常业务状态。

---

## 5. 关键词为什么会搜不到

按可能性排序：

1. **消息在 500 条之外**。看响应里的 `scanned`：等于 `candidate_limit` 就是这个原因。
2. **不是文本消息**。图片消息的正文是 URL，不参与匹配。
3. **超出保留期**。默认 7 天，超出后读路径直接不返回。
4. **消息被撤回或删除**。
5. **关键词里带空格**。首尾空白会被去掉，但中间的空白会原样参与匹配。

---

## 6. 客户端接入建议

- **入口位置**：会话详情页的"搜索"按钮，只搜当前会话。不要做成全局搜索，
  服务端没有这个能力，硬做会变成客户端逐个会话发请求、把限流打满。
- **结果点击**：用 `msg_id` + `msg_time` 定位原消息并高亮，不要依赖 `snippet` 拼正文。
- **空结果文案**：明确写"仅可搜索最近 500 条消息"，不要暗示能搜全部历史。
  用户搜不到时最想知道的就是"为什么搜不到"。
- **退避**：收到 `10012` 后至少等 60 秒再重试。

---

## 7. 已知未验证项

- 该接口**没有在真实服务 + 真实 MySQL 上跑过**（开发机无数据库）。首次上线前建议：
  在测试库造 3 条含同一关键词的消息（其中一条在 500 条以外），确认只返回前两条。
- `qry_hismsgs` 单次拉 500 条的性能**没有压测**。群聊大群、消息体较大时，
  单次请求的耗时与内存占用需要实测。
